# 决策证据隔离与双向评估

## 目标和非目标

决策应从当前可靠事实重新形成观点，而不是继承旧记忆里的仓位走廊、过期价位或反复自证的结论。本轮改变的是证据边界与推理约束，**不是**强制加仓、追涨、保证跑赢基准或调整风险限额。

风险内核、回撤上限、执行授权、HOLD 不下单、订单幂等与重启保护保持不变。旧订单、成交、资金流、净值、事件和记忆版本保留作审计；不删生产数据库。

## 1. 两种历史，不同权限

- **账本事实**：成交、提案动作/准入结果、资金流、净值继续用于归因。资金流不当收益；累计超额不当当日损益；一笔卖出后的少赚不等于整段基准差。
- **模型叙述**：旧模式、旧策略版本、无可信来源标签的记忆不进入当前决策。人工历史复盘仍可归档，但不自动获得交易决策记忆资格。

当前决策记忆须满足：代码签发的策略 epoch、实际交易模式一致、active 状态、原始内容时间有效且不晚于当前时间、年龄不超过 48 小时。旧数据无需迁移或删除即可被隔离。兼容的 `mode=demo` 真钱运行按实际 venue 归入 live scope；shadow 不因机器上存在真钱凭据而变成 live。

首次采用新策略、实际运行模式或交易标的变化时，代码在 `runtime_kv` 持久化新的证据起点；正常重启保留起点。交易上下文的提案、成交、事件、资金流、权益采样与笔记都排除起点前的记录，避免模拟结果被重新总结成实盘记忆。定期复盘窗口在起点处截断并标记 `window_clipped`，未覆盖完整窗口时不输出基准结论；累计历史基准继续留在审计展示中，不冒充本策略版本的成绩。账本和风险 HWM 不被重置。

检索只匹配 JSON `tags` 数组中的完整标签，不再在整段文本中搜子串。排序不靠模型置信度、重复次数或滚动 ID 特权。检索出的模型笔记明确标记为暂定参考，不是已经验证的策略。

代码为新内容签发 provenance；模型不能自填。无内容替换的 UPDATE/MERGE 不刷新内容年龄，不跨 scope 晋升。相同 JSON 内容的完整替换（含换空白/键顺序）也不续期。不同内容仍需调用方保证来自当前事实：单笔反思只取完整的状态/账本 JSON，定期复盘只从确定性窗口事实生成，不递归读旧报告或记忆叙述。

容量淘汰只移除内存索引项；同 ID 重新出现时从 SQLite 历史分配下一个版本，避免覆盖或重复主键。现有记忆总数不是当前可用决策记忆数。

## 2. 市场数据的有效性

- K 线的 `ts_ms` 是 **开盘时刻**，不能拿它与两分钟的网络获取时限直接比较。
- 每个周期独立检查获取时间、bar 周期推进、顺序/连续性、OHLC 合法性和交易所 `confirmed` 标志；组合输出前统一复检。缺失周期显式列入 `missing_frames`，不能用新 15m 数据替过期 1D 数据背书。
- 日线/4H 结构指标只使用已完成 K 线。正在形成的 K 线、已完成收盘突破、只有影线越界分别给出；比较边界不包含正在被比较的 K 线。
- 按需指标保留完整请求窗口，并显式标注 `completed` / `includes_forming`，不把未收盘指标说成收盘确认。
- OI、mark/index、小时级多空比/taker 按各自时间戳与更新周期检查。历史对比按实际时间差，不再假设第 4/24 行等于 4/24 小时前。
- 非 `OK` 工具观察的 payload 在决策输入中为 `null`；审计摘要仍记录收到的内容。不能从旧记忆补回被隔离的数值。辅助数据缺失不等于当前账户/ticker 已陈旧；风险内核自己的时效门禁不变。

**边界**：没有交易所的 bar 内更新时间，无法仅凭 OHLC 未变化就判定正在形成的 K 线冻结；不声称解决了这个不可观测问题。

## 3. 不把滞后标签写成交易禁令

均线斜率未满足趋势阈值改为 `unconfirmed`，不是「已经证明震荡」。阈值本身未为某次行情降低。超买、区间高位、突破、低 RSI 均是事实，不自动生成买卖结论。提示词要求比较延续、反转和无优势解释，避免单个标签拥有永久否决权。

HOLD 的双向评估由**可执行能力**决定，不再只覆盖接近空仓/满仓的任意权重区间：

- 能合法买入：要求 `add_eval`；
- 能合法卖出：要求 `reduce_eval`；
- 混合仓位可以两项同时必填；可用余额、lot、数量/名义金额下限与已知风险状态均参与判断。

`stay` + `keep` 是有效结果；缺理由则拒绝提案，不会自动下单。legacy `cash_tension` / `position_tension` 字段作为新要求的兼容别名保留。

最新同 epoch、同实际模式且 48 小时内的计划可作为 `prior_plan` 进入上下文，附 `review_due`。它用于对比有没有悄悄改变条件，不作为执行指令。`invalid_if` 仍是文本，不宣称有自然语言条件自动执行器。到期复查不要求强制补仓；减仓后价格上涨也不自动判为必须反手。

## 4. 验证与发布

本地验证：

```sh
zig version  # 0.16.0
zig build
zig build test --summary all
```

回归覆盖：遗留/跨模式/过期/未来/未验证记忆隔离、伪造来源标签拒绝、重复内容不续期、索引淘汰后版本连续、混合仓位双向评估、lot/dust 下限、趋势尚未确认的双向突破、假突破影线、各周期陈旧检查、payload 隔离、UTF-8 有界摘要以及旧计划隔离。

上线必须重编嵌入提示词的二进制。若回滚到不认识证据 cohort 的旧二进制后再升级，应另启策略 epoch，不能假定旧程序会维护这条隔离边界。生产发布按本机忽略文件 `DEPLOY.local.md` 核对实例和模式，发布后验证健康、实际模式、决策 epoch、可用工具周期以及新的双向评估字段。不通过自动清仓/加仓来验证。不把真实生产数据放进回归样例或公开文档。

测试证明确定性边界与数据契约，不证明新策略能获利；收益与行为变化需在授权的 shadow/replay 或受控发布后另行观察。

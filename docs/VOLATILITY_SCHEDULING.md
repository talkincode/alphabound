# 高波动自适应决策调度

目标是高波动时更频繁地重新分析，而不是提高下单权限或强迫模型交易。
实现复用原有串行决策循环，不增加线程、任务队列、外部依赖或数据库表。

## 配置与启用

现有配置省略以下字段时，新机制默认关闭；单独升级二进制不会悄悄改变实盘频率。
确认离线回放结果后，在 `[agent]` 中显式配置并重启服务：

```toml
volatility_enter = 0.01
volatility_exit = 0.006
volatility_interval_ms = 180000
volatility_exit_hold_ms = 900000
```

- 最近约 15 分钟的 `(最高 bid - 最低 bid) / 最低 bid >= 1%` 时进入高波动档。
- 高波动档每 3 分钟允许一次新决策，不等待 HOLD 的长复查时间或价格事件空转退避。
- 振幅 `<= 0.6%` 且持续 15 分钟，才退出高波动档。回到两阈值之间会清零退出计时。
- 退出后继续原有调度；切换档位本身不清零连续空转计数或已有 HOLD 延后时间。
- 事件触发的复查（含高波动）不会取消模型已给出的 `review_after`：只有新的可解析
  `review_after`、实际成交，或一次未产出建议的失败（LLM 失败／提案无效）才会改变它。
  否则“HOLD 要求 4 小时后复查”会被一次 3 分钟的复查静默丢弃，常规节奏提前回到基准间隔。
- `decision_min_interval_ms` 始终生效。实际高波动间隔为它与 `volatility_interval_ms` 的较大值。
  本功能不是全局降频器；现有更高优先级事件仍遵守各自规则及全局冷却。
- 关闭时设 `volatility_enter = 0`；其余字段可保留。关闭与启用都需重启。

配置校验：启用时 `0 <= exit < enter < 1`；高波动间隔允许 3–60 分钟，
退出持续时间允许 1–60 分钟。示例阈值是可验证的初始设置，不是收益最优参数。

## 行情覆盖与安全边界

- 只观察实际收到的、通过引擎报价时效检查的交易所 tick。使用交易所时间戳，
  不能把循环中反复读取的旧快照当成新样本；未来报价也不接受。
- 冷启动需要至少 15 分钟连续覆盖，允许相邻观测间隔不超过 90 秒。
  更长中断需要重新预热；不补点、不跨缺失区间外推。
- 固定保存 16 个一分钟高低价桶，保留收到的桶内极值，包括先涨后跌的往返行情。
  最左桶完整保留，因此 15 分钟窗口会向过去多覆盖 0–59,999 毫秒。
- 状态读取使用最后实际观测计算的振幅。窗口允许 90 秒采样间隔，
  但生产触发还必须满足引擎更严格的当前报价 TTL（目前默认 10 秒）。
  不会因为“窗口尚未过期”就用过期现价开启额外决策。
- 人工暂停、强制退出、停机状态仍禁止交易决策。暂停期间可以继续收集行情。
  未配置 LLM、关闭 Agent 或关闭定时决策时，不会由此恢复调用。
- 风控和资金流事件的优先级保持不变；风控准入、执行路径和交易权限不变。
  反思仍按原规则执行，因此每小时 20 次高波动决策不等于最多 20 次全部 LLM 请求。
- 本次没有将现有同步 LLM 调用改成异步。调用变多后仍须观察行情采样缺口、
  调用超时和风控延迟；持续超过 90 秒的阻塞会让窗口重新预热，而非继续高频。

## 可观测性

`AGENT_TRIGGER` 增加：

- `reason = "volatility"`：这次由高波动复查触发。
- `elapsed_ms`：与上次决策触发的实际间隔；首次为 0。
- `volatility.ready / active / range / interval_ms`：当时覆盖状态、档位、
  振幅比例和有效高波动间隔。即使触发原因是风控事件，也记录这些字段。

原有 `interval_ms` 仍表示常规会话间隔，不要把它当作本次实际等待时间。

`GET /api/v1/system` 的顶层 `volatility` 对象还展示启用状态、两阈值、
窗口长度、允许采样间隔、退出计时要求和 `as_of_ms`。
这是主循环发布的缓存快照；客户端须看 `as_of_ms`，不能把旧缓存当作实时状态。
不展示原始报价序列、账户金额或订单标识。

## 验收与上线

```sh
zig build test
zig build replay-scheduler -- public-marks.csv > comparison.csv
zig build -Dtarget=x86_64-linux-musl -Doptimize=ReleaseSafe
```

回放说明见 [SCHEDULER_REPLAY.md](SCHEDULER_REPLAY.md)。回放使用真实调度器，
只改变高波动开关；双方均假定每次 HOLD 并要求四小时后复查。
它验证调度响应，不复现历史模型决策，也不预测收益或实际未来调用总数。
分钟样本看不到所有桶内极值，并有最多一个采样周期的触发时间误差。

上线前检查平稳窗口旧/新结果一致、急涨急跌窗口增加的是预期复查、
全局冷却不被突破。生产配置、地址、备份与验收结果只在本机忽略的部署记录中维护。
上线后核验运行时参数、健康检查、采样覆盖与新触发记录，并继续观察成交质量；
不要用调用次数增加替代收益验收。
